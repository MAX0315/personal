# 黯马媒体工作台 2.5.3 · 抖音、视频号与小红书修复版

正式网址：https://anma-media-workbench-xhs-20261014.netlify.app/?v=2.5.3

本项目按用户要求复制当前线上 2.5.0 的公开 HTML、CSS、JavaScript 和品牌资源，保留现有布局，在本机继续迭代。另一台电脑的原始服务器源码未复制；抖音、视频号、B 站、YouTube 及需要平台登录的小红书笔记继续调用原站云端服务。公开小红书视频改由本项目的独立 Netlify Function 提取、下载、验证并保存。

## 本次修复

- 抖音短链接先由服务端读取官方跳转，确认精确作品 ID，再直接启动官方作品页任务；支持含连字符的分享短链接，不再让浏览器在短链页面等待 15 秒后中断。
- 短链接解析最多五跳、总时限八秒，仅允许抖音官方域名；不执行页面脚本，不从推荐内容猜测作品。
- 抖音导航超时显示中文重试提示，技术诊断默认折叠，并隐藏链接查询参数、片段和用户信息。
- 抖音视频与视频号同样经过本站完整字节和 MP4 核验后显示“文件已验证”，纯图文结果保留原有处理流程。
- 视频号和原后台媒体文件改为独立服务端请求转发，保留当前登录会话，防止跨站 Netlify 内部上下文污染导致文件接口 500。
- 所有原后台文件均提供准确的 Range 分段；大文件单次最多返回 4 MiB，避免超过平台流式响应上限。
- 视频号文件在实际下载完整字节并核对 MP4 容器、轨道和时长后，再显示文件已验证；完整核验总量上限为 32 MiB，较大文件仍支持分段保存。
- 预览错误同时提示文件读取和编码问题，避免把服务器错误误诊为浏览器不支持编码。

- 识别完整分享文案、xhslink.cn / xhslink.com，逐跳保留官方分享参数。
- 使用官方移动分享页面公开返回的视频信息，避免公开笔记先进入桌面扫码和安全验证流程。
- 核对笔记 ID、官方 CDN、目标时长、接收长度和完整 MP4 容器，优先 H.264 播放版本。
- 文件保存在 Netlify Blobs 中，仅原会话可读取；准确提供分段下载。任务与文件访问有效期为一小时。
- 返回笔记完整正文，可直接复制或保存。
- 空结果不再显示成功，未验证的媒体不再显示完成验证；任务结果更新会重新绘制。

`.netlify/` 已加入忽略规则，部署始终明确指定新站点 ID，避免覆盖工作区原项目。

## 使用与维护

`npm install`、`npm test`。`npm run dev` 在 http://localhost:8097 启动本地预览。

本地开发使用内存保存临时任务；云端使用 Netlify Blobs。创建站点时需要将访问范围设置为公开，才能与原站相同地直接打开使用。原有平台服务依赖上方原站仍正常运行；若要完全独立迁移所有平台，需要另一台电脑上的服务器源码。
